API

Apa itu API?

API (Application Programming Interface) adalah antarmuka yang memungkinkan software berkomunikasi dengan software atau layanan lain melalui aturan tertentu.

Analogi restoran: Client = pelanggan yang lapar, API = pelayan yang mencatat & mengantar pesanan, Server = dapur yang benar-benar memasak datanya.

API FLOW

Alur komunikasi Client ↔ Server

Browser mengirim HTTP request ke endpoint API. Server memproses request dan mengembalikan HTTP response.

Client → Request → API/Server → Response → Client. Untuk sprint ini fokus utama kita adalah GET, yaitu mengambil data.

Browser→ Request →API / Server→ Response →Browser
API ANATOMY

Kenali bagian-bagian API.

Endpoint adalah alamat resource. HTTP method menjelaskan operasi. Request adalah informasi yang dikirim client. Response adalah hasil dari server.

Endpoint

Alamat resource. Contoh: https://api.example.com/users

Method

GET = ambil, POST = buat, PUT/PATCH = ubah, DELETE = hapus

Request

Informasi yang dikirim client (header, body, params)

Response

Hasil balasan dari server (status + data)

HTTP

Response punya status.

HTTP status membantu kita mengetahui hasil request.

Jangan menganggap semua request pasti berhasil — status code adalah hal pertama yang harus dicek.

200 OKBerhasil
404 Not FoundResource tidak ditemukan
500 Server ErrorMasalah di server
JSON

Data API sering dikirim sebagai JSON.

JSON (JavaScript Object Notation) adalah format pertukaran data berbasis teks yang mudah dibaca manusia dan diproses program.

JSON adalah format data (teks), bukan pengganti JavaScript. JSON.parse() mengubah teks JSON menjadi object JS.

Fetch API: membuat HTTP request

Fetch API adalah API browser yang digunakan JavaScript untuk melakukan network request.

Fetch mengembalikan Promise. Coba jalankan demo di kanan — datanya benar-benar diambil dari API sungguhan.

PROMISE

Kenapa muncul Promise?

Network request membutuhkan waktu. Hasilnya tidak selalu tersedia pada saat baris kode dijalankan.

Keadaan Promise: Pending → Fulfilled atau Rejected. Perhatikan status berubah setelah 1.5 detik pada demo ini.

ASYNC AWAIT

Tuliskan asynchronous code dengan lebih nyaman.

async menandai function sebagai asynchronous. await menunggu hasil Promise di dalam function tersebut.

async/await bukan membuat network request menjadi synchronous; ia hanya membuat penulisannya lebih mudah dibaca dibanding .then() berantai.

BREAKDOWN

Pahami alur data.

fetch(url) → Response → response.json() → JavaScript data → proses data → DOM.

fetch() mengambil response. response.json() membaca body JSON secara asynchronous. Setelah menjadi data JavaScript, kita dapat melakukan forEach/map/filter lalu merender hasilnya.

fetch(url)→Response→.json()→data JS→proses→DOM
RESPONSE

Response bukan langsung data.

Object yang diterima dari fetch adalah Response. Kita perlu memeriksa status sebelum membaca body.

Selalu cek response.ok sebelum memanggil response.json(). Demo ini sengaja memakai endpoint yang tidak ada.

ERROR

Request bisa gagal. Gunakan try/catch.

Aplikasi harus memikirkan kondisi gagal, bukan hanya kondisi sukses.

Gunakan response.ok untuk memeriksa status HTTP dan try/catch untuk menangkap error jaringan. Tampilkan feedback yang jelas kepada pengguna.
