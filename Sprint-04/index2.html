01. Konsep Dasar Data
02 / 18

Website Modern Bekerja dengan Data Dinamis

Pada website statis, seluruh data ditulis secara manual di dalam dokumen HTML (Hardcoded). Sedangkan aplikasi web modern memisahkan struktur tampilan dengan data yang bersumber dari API/Database.

Pendekatan Statis (Tradisional)

Semua teks & daftar produk ditulis langsung di file HTML. Jika ada pembaruan, kamu harus mengedit file index.html secara manual dan mengunggahnya kembali ke server.

Pendekatan Dinamis (Modern API)

HTML hanya menyediakan kerangka wadah. JavaScript meminta data terbaru dari API server, lalu merender antarmuka secara otomatis tanpa perlu mengubah kode HTML.

Prinsip Inti: Memisahkan User Interface (HTML/CSS) dengan Data Management (API/JSON) adalah fondasi utama pengembangan web modern.
02. Memahami API
03 / 18

Apa itu API (Application Programming Interface)?

API adalah jembatan komunikasi terstandar yang menghubungkan antarmuka pengguna di sisi browser (Client) dengan penyedia data di sisi server.

Alur Komunikasi Client - API - Server

Client (Browser) Kirim Request ke API
API Endpoint Jembatan Penghubung
Server & Database Memproses & Siapkan Data
Data JSON Hasil Olahan Server
API Response Kirim Balik ke Browser
DOM Render Tampil di Antarmuka UI
Kesimpulan: Frontend tidak perlu tahu bagaimana database server dikelola. Frontend cukup mengirim permintaan ke API, dan API akan memberikan data dalam format JSON.
03. Protokol HTTP
04 / 18

Anatomi Komunikasi HTTP Request & Response

Setiap komunikasi antara browser dan server API terdiri dari komponen terstruktur berikut:

1. Endpoint (URL)

Alamat spesifik tujuan request.
Contoh: api.tvmaze.com/shows/1

2. HTTP Method

Aksi yang dilakukan:
• GET: Ambil data
• POST: Kirim data baru
• DELETE: Hapus data

3. Request Header

Metadata seperti tipe format data atau token otorisasi keamanan.

4. HTTP Response

Balasan server yang memuat Status Code dan Data Payload.

200 OK Permintaan berhasil diproses.
404 Not Found Alamat endpoint tidak ditemukan.
500 Server Error Terjadi kendala pada server backend.

05. Alur Async
06 / 18

Sync vs Asynchronous Execution

Mengambil data dari internet membutuhkan waktu (1-3 detik). Mekanisme asynchronous mencegah seluruh tampilan browser membeku saat menunggu respon jaringan.

Synchronous (Blocking)

Baris berikutnya harus menunggu baris saat ini selesai total. Jika sebuah request memakan waktu lama, browser akan mengunci interaksi pengguna.

console.log("Baris 1");
ambilDataLama(); // Blocking 5 detik!
console.log("Baris 3");

Asynchronous (Non-Blocking)

JavaScript mendelegasikan proses lambat ke latar belakang (Web API). Kode di bawahnya langsung dieksekusi tanpa jeda.

console.log("Mulai");
fetchDataAsync(); // Berjalan di background
console.log("Selesai (Langsung jalan!)");
Karakteristik JS: JavaScript secara default adalah single-threaded. Model Asynchronous memungkinkan aplikasi menangani tugas I/O jaringan dengan lancar tanpa freeze.
06. JavaScript Promise
07 / 18

Memahami Promise (Janji Asynchronous)

Promise adalah objek JavaScript yang mewakili status dan hasil dari operasi asynchronous di masa depan. Memiliki 3 state utama:

1. Pending

Sedang memproses request jaringan.

2. Fulfilled (Resolved)

Permintaan sukses dan data diterima.

3. Rejected

Permintaan gagal karena error/timeout.
